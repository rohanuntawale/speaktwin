1 · What SpeakTwin Is

SpeakTwin is a real-time speech coaching system. It listens while you speak, analyses delivery every 2.5 seconds, and returns actionable feedback — pace, loudness, vocal variety, filler words, clarity, and a composite confidence score.

1.1 The problem

People are poor judges of their own delivery. You cannot hear your own filler words while producing them, you cannot tell that you have drifted monotone, and you rarely notice you have accelerated past the point of intelligibility. Recording yourself helps, but reviewing recordings is slow and most people never do it.

SpeakTwin closes that loop to a few seconds. You speak, and within one chunk you see what a listener would notice.

1.2 Design constraints

Four constraints shape every decision in this codebase:

ConstraintConsequence
Sub-3-second latencyAnalysis runs on 2.5 s chunks. Every component has a hard time budget; anything slower than the chunk rate causes backlog.
Must run without a GPUDefault path is pure DSP plus a quantised int8 Whisper. Neural models are optional and off by default.
Must run on a serverA deployed server has no microphone, so capture happens in the browser and audio is POSTed as chunks.
Must degrade, never breakEvery optional component — cloud STT, LLM coaching, all eight neural models — fails to a working fallback rather than an error.

2 · System Architecture

2.1 Why capture is client-side

The original prototype used sounddevice to read the server's microphone. That works on a laptop and is impossible on a deployed server, which has no audio hardware. Capture therefore lives in the browser: the Web Audio API reads the microphone, a hand-written encoder produces WAV, and chunks are POSTed to the backend.

Consequence

The backend is stateless with respect to audio hardware and scales horizontally. The legacy server-side capture module is retained for single-machine kiosk use, with its sounddevice import guarded so the module stays importable without the package.

2.2 Concurrency model

FastAPI runs async def handlers on the event loop. Whisper inference, autocorrelation, and outbound HTTP are all blocking, so running them inline stalls every other request in the process. The handler is async only to stream the upload; all real work is dispatched via run_in_threadpool.

async def analyze_blob(audio_file: UploadFile = File(...), ...):
    raw = await _read_limited(audio_file, settings.max_upload_bytes)
    audio, src_sr = await run_in_threadpool(prepare, raw, settings.max_audio_seconds)
    return await run_in_threadpool(_perform_full_analysis, audio, session_id, src_sr)

Models that are not thread-safe — Whisper, and every torch module — are additionally serialised behind per-model locks.

3 · Request Lifecycle

What happens between speaking a word and seeing feedback, in order.

Step 1 — Capture (browser)

On mic activation the frontend requests a 16 kHz AudioContext, attaches a ScriptProcessorNode, and accumulates samples. When the buffer reaches one chunk (2.5 s × the actual sample rate, which may differ from the 16 kHz hint), it is snapshotted and encoded.

Detail that matters

The browser may ignore the sample-rate hint. The frontend therefore sends audioCtx.sampleRate — whatever it truly got — and the backend resamples. Assuming 16 kHz here is precisely the bug described in §4.2.

Step 2 — Session association

On start, the client calls POST /api/session and attaches the returned session_id to every chunk. Without one, analysis still works but loses cross-chunk smoothing, cumulative totals, decoder context, and the adaptive silence gate.

Step 3 — Upload & validation

The body is streamed in 64 KB reads and aborted the moment it exceeds MAX_UPLOAD_BYTES, so an oversized payload is rejected part-way rather than buffered whole. Decoding is capped independently at MAX_AUDIO_SECONDS.

Step 4 — Decode & normalise

The header is inspected through SoundFile before any samples are read, so only the permitted number of frames is decoded. Audio is mono-mixed, converted to float32, resampled to exactly 16 kHz, and scrubbed of NaN/Inf.

Step 5 — Acoustic analysis

Energy (RMS → dBFS), pitch (windowed autocorrelation with voiced gating and octave correction), and pauses (frame RMS against a dBFS threshold). If the neural layer is enabled, CREPE and Silero override these results here.

Step 6 — Silence gate

If the chunk is silence, transcription is skipped entirely. This matters because Whisper hallucinates confidently on silence. The gate is adaptive per session (§9.3), and when Silero VAD is enabled its verdict supersedes the energy threshold.

Step 7 — Transcription

The resolved engine transcribes the chunk, receiving the tail of the session's previous transcript as initial_prompt so words are not mangled at chunk seams. On failure the response is flagged degraded and acoustic metrics — which remain valid — are still returned.

Step 8 — Linguistic analysis

Fillers (context-aware), keywords (longest-match n-grams), clarity (MATTR), and WPM from word count over chunk duration.

Step 9 — Scoring & coaching

Four sub-scores are computed and combined by weight. Threshold rules generate coaching messages. If configured and not rate-limited, an LLM produces one punchy headline line; otherwise the first rule-based warning is promoted.

Step 10 — Session fold

The result is folded into the session: totals accumulate, EMAs update, the loudness history extends, and the transcript segment is appended. The updated summary rides back with the response.

Step 11 — Render

The client animates meters, the confidence ring (preferring the smoothed score), the breakdown bars, and appends the transcript with keyword and filler highlighting. The transcript is HTML-escaped before highlight spans are injected.

4 · Audio Ingestion

backend/services/audio_io.py

4.1 The contract

Everything downstream assumes mono, float32, exactly 16 kHz. This module is the single place that guarantees it.

def prepare(data: bytes, max_seconds, target_sr=16000) -> tuple[np.ndarray, int]:
    mono, src_sr = decode(data, max_seconds=max_seconds)   # header-limited read
    audio = resample(mono, src_sr, target_sr)              # polyphase
    audio = np.nan_to_num(audio, nan=0.0, posinf=0.0, neginf=0.0)
    return np.ascontiguousarray(audio, dtype=np.float32), src_sr

4.2 The sample-rate bug this module exists to fix

Bug found and fixed

The original route read the sample rate and discarded it:

y, sr = sf.read(io.BytesIO(audio_bytes))   # sr never used again

Everything downstream hardcoded 16 kHz — WPM as len(audio)/SAMPLE_RATE, pitch as sr=SAMPLE_RATE, and the Groq re-encode. A client sending 44.1 or 48 kHz audio had its pitch and speaking rate wrong by roughly 3×. It only appeared to work because the frontend happened to request 16 kHz.

4.3 Resampling

Polyphase resampling via the reduced integer ratio, so common conversions are exact rather than approximated:

divisor = math.gcd(src_sr, dst_sr)
resample_poly(audio, dst_sr // divisor, src_sr // divisor)
# 48000 → 16000 reduces to up=1, down=3 — exact

4.4 Bounded decoding

Reading through SoundFile rather than sf.read allows inspecting the header and decoding only the permitted frames. A one-hour file uploaded to a 30-second endpoint costs 30 seconds of decode, not an hour.

5 · Acoustic Analysis

backend/services/audio_analysis.py — numpy and scipy only, no librosa.

5.1 Energy

RMS amplitude, converted to dBFS for all threshold comparisons:

rms   = sqrt(mean(x²))
dBFS  = 20 · log₁₀(rms)
Why dBFS rather than linear RMS

Thresholds on linear RMS swing wildly with microphone gain, OS input level, and browser AGC. On a log scale the same thresholds degrade gracefully. The linear constants are derived from the dBFS ones, so the two can never drift apart.

ThresholddBFSEquivalent RMSMeaning
SILENCE−45≈ 0.0056No speech detected
LOW−36≈ 0.0158Speaking too softly
HIGH−12≈ 0.2512Speaking too loudly
HARD FLOOR−60≈ 0.001Adaptive gate never goes below this

5.2 Pitch — windowed autocorrelation

64 ms Hann-windowed frames, 32 ms hop. For each frame:

  1. Voiced gate — frames below −50 dBFS are skipped. Silence has no pitch, and including it corrupts the standard deviation that drives 25% of the confidence score.
  2. Mean removal and windowing — eliminates DC bias and edge discontinuity.
  3. FFT autocorrelation, normalised by lag-zero energy.
  4. Restricted lag search — only lags corresponding to 60–400 Hz are considered.
  5. Voicing threshold — normalised peak below 0.35 means unvoiced; frame discarded.
  6. Local-maximum check — see the bug box below.
  7. Octave correction — autocorrelation peaks at every multiple of the true period, so the raw argmax often lands an octave low. Sub-multiple lags are preferred when at least 85% as strong.
  8. Parabolic interpolation — sub-sample peak position for finer frequency resolution.
Bug caught by the test suite

A 20 Hz signal — desk rumble, handling noise, DC drift — was reported as 400 Hz. Its true period lies outside the search range, so the in-range maximum pins to the boundary lag, and the boundary was taken at face value. A desk bump would trigger "Pitch high, relax your voice". Fixed by requiring the peak to be a genuine interior local maximum.

Robust averaging

The reported mean discards residual octave outliers before averaging — values outside [median/1.6, median×1.6] are dropped — so a handful of bad frames cannot drag the reported pitch around.

5.3 Pause detection

Per-frame RMS is computed with a strided view rather than a Python loop, then compared against the dBFS gate. Both the total silent fraction and the longest consecutive run are reported; the latter distinguishes a hesitation from generally sparse speech.

6 · Speech-to-Text

openaiOpenAI whisper-1, falling back to local on failure

6.2 Concurrency

Not thread-safe

WhisperModel.transcribe is not safe to call from several threads at once, and this service runs inside FastAPI's threadpool. The original code locked only loading. Inference is now serialised behind a separate _inference_lock.

6.3 Cross-chunk context

Each chunk is decoded with the tail of the session's transcript (220 characters) as initial_prompt. Without it, every 2.5 s boundary cuts a word in half and the decoder has no way to recover it. condition_on_previous_text=False is set separately to prevent the decoder looping on its own output — the classic repeated-phrase hallucination.

6.4 Silence handling

Two independent defences: the silence gate skips transcription entirely for quiet chunks, and Silero VAD (via vad_filter) trims silence before decoding, with a no-VAD retry if the ONNX runtime is unavailable.

7 · Linguistic Analysis

7.1 Context-aware filler detection

backend/services/filler_detection.py

Filler words split into two classes. Hesitation sounds are always fillers. Discourse markers have legitimate lexical uses and are only counted in filler positions.

WordRuleCountedNot counted
um, uh, eralwaysHesitation sounds have no lexical use
soclause-initial"So the solution is…""…so we shipped it"
wellclause-initial"Well, that went badly""It went well today"
rightclause-final"That is exactly right""The right answer"
likelexical-context"it was like really fast""I like this", "would like to"

Detection walks the token stream longest-match-first, so you know beats a bare know, and a recognised phrase used lexically is skipped without re-testing its shorter prefixes.

7.2 Keyword detection

The same longest-match walk over target vocabulary. artificial intelligence registers once as a phrase rather than twice as separate words. N-grams never span punctuation, so a phrase cannot straddle a clause boundary.

7.3 Clarity — why MATTR

backend/services/clarity_analysis.py

The measurement problem

Plain type-token ratio (unique ÷ total) is strongly length-dependent. A five-word chunk almost always scores 1.0; a hundred-word one rarely clears 0.6. A per-chunk score and a whole-session score are therefore not comparable on the same axis.

MATTR — moving-average type-token ratio — averages TTR across every sliding 25-word window, which stays stable as text grows. Texts shorter than one window fall back to plain TTR. Raw TTR is still reported for display.

mattr  = mean(TTR(window) for window in sliding(words, 25))
score  = min(1.0, mattr / 0.75) × 100 − filler_rate × 300

An intermediate design using root TTR was rejected during development: it under-rewards the short chunks SpeakTwin actually sends, scoring a perfectly clear six-word utterance at 38/100.

8 · Scoring & Feedback

8.1 Confidence composite

backend/services/confidence_score.py

score = 100 × ( 0.25·wpm + 0.25·pitch_variation + 0.20·energy + 0.30·fluency )
Sub-scoreWeightCurve
WPM25%1.0 inside 120–160; falls linearly to 0 at 60 WPM outside the band
Pitch variation25%0 at σ=0; 0.4 at σ=15; 1.0 at σ≥35, linear between
Energy20%Piecewise: 0 below −45 dBFS, ramps to 1.0 at −36, flat to −12, decays to 0.4
Fluency30%1.0 at zero fillers; 0 at twice the "high" rate (0.16 per word)
Design note

The energy sub-score was a three-step ladder (0.3 / 1.0 / 0.5). A speaker drifting quiet fell off a cliff rather than sliding. It is now piecewise-linear on the dBFS axis, so the score tracks the drift continuously.

8.2 Fitting the weights — and what the data actually supports

25/25/20/30 is not derived from data; it is a plausible prior. training/train_confidence_scorer.py fits it against speechocean762's human ratings, keeping the sub-score functions — which encode real domain knowledge — and fitting only their combination, so the output drops straight back into config.

Measured on 400 utterances, target fluency: R² = 0.20.

WeightCurrent → fittedVerdict
wpm0.25 → 0.39Trustworthy — σ 0.32, real variation
pitch_variation0.25 → 0.38Trustworthy — σ 0.22
energy0.20 → 0.10Unreliable — σ 0.010; studio recordings all at one level
filler_usage0.30 → 0.13Unreliable — 95% of clips contain zero fillers
Why the weights are not yet adopted

A regression will happily assign a confident weight to a feature that never varies. The script detects near-constant features, refuses to endorse their weights, keeps the existing values, and renormalises the rest. Two of the four numbers here are meaningless, so importing all four would make the score worse while looking more scientific.

speechocean762 is read speech scored for pronunciation, not spontaneous public speaking. Closing this properly needs a corpus of rated spontaneous delivery — none is openly available.

8.3 Feedback engine

Threshold rules over five categories — loudness, pitch, pitch variation, speed, fillers, pauses — each producing a message typed info, success, or warning. Overall status derives from the warning count: excellent (zero warnings) through poor (four or more), with silent short-circuiting everything.

Pitch messages are suppressed entirely when nothing voiced was detected, rather than reporting a confident 0 Hz.

8.4 LLM coaching line

backend/services/llm_feedback.py — optional, via OpenRouter.

Defended on three fronts, because it sits on the critical path of every chunk:

  • Timeout and single retry — a slow provider cannot stall the request indefinitely. The original client had no timeout at all.
  • Per-session throttle — a 2.5 s cadence would otherwise mean ~24 paid calls per minute per speaker. Default minimum interval of 8 s cuts that to ~7, and the slot is reserved under a lock so concurrent chunks cannot both pass.
  • Transcript cap — prompt size stays bounded regardless of session length.

Every failure path returns None and the rule-based message is promoted instead.

9 · Session Layer

backend/services/session_store.py

Without sessions every chunk was analysed in isolation and discarded. Four capabilities depend on cross-chunk state:

9.1 Cumulative totals

Filler and keyword counts previously lived only in browser memory and vanished on refresh. They now accumulate server-side and ride back with every response.

9.2 EMA smoothing

A confidence score computed from 2.5 s of audio is statistically noisy — one word is 24 WPM of granularity. Exponential moving averages give a trend line:

ema = α · value + (1 − α) · previous          # α = 0.4, seeded by the first observation

The frontend displays confidence_smoothed when present. Peak confidence is tracked separately as the raw maximum.

9.3 Adaptive silence gate

A fixed threshold cannot tell a quiet microphone from a quiet room. The session tracks recent chunk loudness and derives a gate from the 10th percentile plus 8 dB headroom:

gate = max(HARD_FLOOR, min(ABSOLUTE_SILENCE, p10 + 8))
Deliberately asymmetric

The absolute threshold is a ceiling, never a floor. A quiet microphone lowers the gate so speech still reaches the transcriber; a noisy room can never raise it and start transcribing background hiss. The hard floor at −60 dBFS bounds it below.

9.4 Decoder context

The transcript tail feeds the next chunk's initial_prompt (§6.3).

9.5 Storage and eviction

In-process, TTL-bounded, guarded by a reentrant lock. Sessions are ephemeral coaching state, not records worth a database; reports are handed to the client as JSON to persist wherever it likes. Expired sessions are dropped on access, and capacity overflow evicts oldest-first.

Bug caught by the test suite

Pruning ran before insertion, so it measured capacity without the incoming session and the store settled one over max_sessions. Fixed by inserting first, then pruning.

10 · Deep Learning Layer

backend/services/ml/ — eight models, all off by default.

10.1 The contract

Every module exposes is_enabled() and an analysis function, returns None when the feature is off or its dependency is absent, and never raises into the request path. That contract is what keeps a base pip install -r requirements.txt fully valid.

10.2 The registry

One component owns loading, caching, and reporting. Lazy (nothing imported until first use — importing torch alone costs seconds), once (per-model load lock), optional (a missing package disables one feature and records why), and serialised (torch modules are not concurrency-safe).

A model that fails to load is never retried, so a broken dependency costs one startup attempt rather than an attempt per request.

10.4 Why the acoustic filler detector must exist

A structural limitation, not a tuning problem

Whisper was trained largely on cleaned transcripts and routinely deletes "um" and "uh". Enabling its VAD filter trims the hesitation regions as well. So transcript-based filler counting under-counts structurally — no regex improvement can fix it, because the evidence has already been deleted before the text is produced. It survives only in the waveform.

No suitable public checkpoint exists, so training/train_filler_detector.py fine-tunes a WavLM backbone into a frame-level classifier on PodcastFillers. Consecutive frames sharing a label collapse into one event, so forty frames of "um" count as one filler.

Merge strategy

Acoustic and text counts merge by maximum per label, not sum. When Whisper does keep an "um", both detectors see the same event and adding them would double-count it.

10.5 Two bugs found by running the models

Emotion labels silently wrong

superb/wav2vec2-base-superb-er emits IEMOCAP abbreviations — ang, hap, neu, sad — not full words. The label sets contained only long spellings, so audio classified 98% angry scored tension 0.003: a furious delivery reported as perfectly calm. Both vocabularies are now mapped, and unrecognised labels surface in unmapped_labels with a warning rather than reading as zero.

SpeechBrain broken on Windows

ECAPA failed with WinError 1314: A required privilege is not held. SpeechBrain symlinks model files out of the Hugging Face cache, and Windows refuses without Developer Mode or admin rights. The loader now requests real copies via LocalStrategy.COPY_SKIP_CACHE, with a fallback for older releases.

11.3 Vulnerabilities fixed

Traceback disclosure

The original error handler returned traceback.format_exc() in the response body, exposing file paths and internal structure to anyone who could trigger an error. The traceback now goes to logs only; detail appears in responses only under DEBUG.

Invalid CORS combination

allow_origins=["*"] with allow_credentials=True is forbidden by the CORS specification and rejected by browsers outright. Credentials are now enabled only alongside explicit origins.

Transcript HTML injection

The frontend injected transcript text via innerHTML for highlighting, without escaping. Text is now escaped before highlight spans are added, and regex metacharacters in filler and keyword names are escaped too.

Cost exposure

/api/analyze can spend money at a cloud provider on every call. On a publicly reachable instance, set API_KEY — otherwise anyone can drain your Groq and OpenRouter credit.

14.3 Licences drive what you can ship

Read before training

A model generally inherits its training data's restrictions. PodcastFillers and TED-LIUM are non-commercial. If SpeakTwin is ever commercial, build only on CC0 / CC BY corpora: Common Voice, VoxPopuli, AMI, speechocean762, LibriSpeech.

14.4 Training the filler detector

python training/train_filler_detector.py \
    --data-dir data/podcastfillers --build-manifest \
    --output-dir models/filler-detector \
    --backbone microsoft/wavlm-base-plus --epochs 3 --fp16

Frame labels are overwhelmingly the negative class, so the script reports positive-class precision, recall, and F1 alongside accuracy. Accuracy alone will look excellent while the model predicts "none" for everything.

15 · Frontend

frontend/ — vanilla HTML, CSS, and JavaScript. No framework, no build step.

15.1 Capture chain

getUserMedia → AudioContext(16000) → MediaStreamSource
             → ScriptProcessorNode(4096) → accumulate
             → encodeWav(samples, actualSampleRate) → POST

The WAV encoder is hand-written: a 44-byte RIFF header followed by 16-bit PCM converted from Float32. Sending WAV rather than the browser's native WebM/Opus means the backend never needs a codec beyond libsndfile.

15.3 Bugs fixed

Static assets 404 at the root

index.html loads style.css and app.js with relative paths, but the frontend directory was mounted only at /static — so from / those resolved to /style.css and 404'd. The directory is now mounted at both /static and /, registered after the API router so /api/* still wins.

Hardcoded port mismatch

API_BASE pointed at localhost:8002 while the server defaulted to 8001 and the README said 8000. Now same-origin by default, overridable via window.SPEAKTWIN_API_BASE.

16.2 What the tests caught

Three defects were found by the suite rather than in production: the pitch boundary bug (§5.2), the session eviction off-by-one (§9.5), and a namespace collision where the registry instance shadowed the registry module, making it unreachable by dotted path.

16.3 Deployment

# Base (~1 GB) - DSP + Whisper, no neural extras
docker build -t speaktwin .

# With the DL layer (~3-4 GB) - CPU torch + all models
docker build -f Dockerfile.ml -t speaktwin:ml .
docker run -p 8000:8000 --env-file .env speaktwin:ml

The image installs libsndfile1, pre-downloads Whisper weights into an image layer, and runs unprivileged as UID 10001 with a health check.

Single worker, deliberately

The session store and rate limiter are in-process. Multiple workers would each keep their own copy — sessions would appear and disappear depending on which worker served the request. Scaling past one replica requires moving both to a shared backend such as Redis.

16.4 CI

Three jobs: the base suite across Python 3.10–3.12 without ML extras, an ml-extras job that installs CPU torch and asserts the neural layer stays inert by default, and a Docker build.

17.3 Rejected, and why

  • Server-side microphone capture — impossible on a deployed server; retained only as legacy.
  • librosa in the request path — heavy dependency for functionality replaced in pure numpy. It returns only as a transitive dependency of torchcrepe in the ML extras.
  • Root TTR for clarity — length-normalises in the wrong direction for short chunks; MATTR chosen instead.
  • Audio overlap between chunks — would duplicate words at seams. Decoder prompt carryover achieves the same benefit without the deduplication problem.
  • Summing acoustic and text filler counts — double-counts the same event; maximum-per-label used instead.
